# QTranslate Google 翻譯服務修正

修好 QTranslate 6.10.0 無法翻譯的問題。

## 問題原因

QTranslate 的各家翻譯服務不是寫死在 `QTranslate.exe` 裡，而是放在
`Services\<服務名稱>\Service.js` 這種純文字檔，程式執行時才去讀取並在內建的
JScript 引擎裡執行。所以壞掉的是那段 JS 連的網址，不是程式本體。

原始的 Google 服務連的是：

```
https://translate.google.com/translate_a/single?client=gtx&...&tk=<自行計算的權杖>
```

Google 已經停止對第三方開放這個端點。現在它回傳的不是翻譯結果，而是一頁
防濫用的「Sorry…」HTML，QTranslate 解析不出任何內容，畫面就一片空白。

## 修法

改連 Chrome 擴充套件用的端點，它提供同樣的資料、不需要權杖，而且加上 `dj=1`
之後會回傳正規的 JSON，而不是舊版那種稀疏陣列：

```
https://clients5.google.com/translate_a/single?dj=1&client=dict-chrome-ex&dt=t&dt=bd&dt=rm
```

翻譯、拼音、字典詞條（含詞性與同義詞）全部保留，輸出格式與原本完全一致。
語音朗讀（`translate_tts`）在 `translate.google.com` 上仍然正常，因此
`serviceHost()` 會針對 `Capability.LISTEN` 回傳原本的網域。

## 換行斷句修正

從 PDF 選取的文字，以及螢幕 OCR 辨識出來的文字，每一行結尾都帶著硬換行。
直接送去翻譯的話，翻譯引擎會把每一行當成獨立句子，於是
`...to power the digital / inputs.` 被拆成兩段不相干的譯文，標題也會被
後面的內文吞掉，變成 `Chapter 4 I/O Introduction Each RIO comes with...`。

修正後的 `Service.js` 會在送出前重建段落結構。判斷依據是**版面寬度**：

> 排版折行的那一行，是因為下一個字擠不下才斷的；
> 刻意換行的那一行（標題、段落結尾），斷的時候還有空間。

所以規則就是一句話——**下一行的第一個字，塞得進上一行嗎？**
塞得下代表那個換行是刻意的，保留；塞不下才是折行，接回去。

| 情況 | 處理 |
| --- | --- |
| 一般折行 | 接回同一句 |
| 標題（明顯短於版面寬度且非句尾） | 獨立成行，並補一個空行 |
| 段落結尾 | 保留換行 |
| 空行 | 保留為段落分隔 |
| 項目符號、編號清單 | 各自獨立成行 |
| `compat-` / `ibility` | 接成 `compatibility`（去掉連字號）|
| `RIO-` / `47xxx` | 接成 `RIO-47xxx`（保留連字號）|
| 中日韓文字相接 | 接回時不插入空格 |
| 整段最寬不到 45 字元 | 視為選單、表格、標題列，完全不處理 |
| 整段最寬超過 200 字元 | 視為已被接過的文字（例如開了「移除換行字元」），完全不處理 |

翻譯引擎會原樣保留收到的換行，所以來源的結構對了，譯文的結構就跟著對。

因為選字翻譯與畫面 OCR 翻譯都會經過同一個 `serviceTranslateRequest`，
這項處理對兩者同時生效。

### 必須關閉「移除換行字元」

QTranslate 選項裡的「移除換行字元」（`RemoveLineBreaks`）會在文字進入來源框
**之前**就把所有換行砍光，位置比 `Service.js` 更前面。一旦開啟，上面所有
判斷都拿不到換行資訊，標題與段落會全部黏成一整段。**請保持關閉。**

代價是主視窗上半部顯示的原文會保留原本的斷行。那只是顯示，譯文不受影響。

## 使用方式

有兩種方式，看目標電腦的狀況選一種。

### 新電腦：執行安裝檔

雙擊 `dist\QTranslate-Setup.exe`，按「安裝」即可。它會跳出 UAC 要求管理員權限
（寫入 Program Files 需要），然後：

1. 解壓縮 QTranslate 到 `C:\Program Files (x86)\QTranslate`（位置可改）
2. 套用完整設定（見下表）
3. 建立開始功能表捷徑，可選桌面捷徑與開機自動啟動（預設勾選）
4. 註冊到「應用程式與功能」，之後可從那裡解除安裝
5. 啟動 QTranslate

安裝檔自帶 .NET 執行環境，目標電腦**不需要**預先安裝任何東西。

裝完之後**只剩填入 OCR 金鑰一件事**，其餘都設好了：

| 設定 | 值 |
| --- | --- |
| 按住 Ctrl 選取文字 | 直接跳出翻譯 |
| 連點兩下 Ctrl | 畫面框選翻譯 |
| Ctrl+Q / Ctrl+Alt+Q / Ctrl+E | 彈出視窗／主視窗／朗讀 |
| 移除換行字元 | 關閉（必須，否則標題與段落會黏在一起）|
| 主視窗版面 | 收合原文框、隱藏語言工具列與服務圖示列 |
| 主視窗尺寸 | 700×440，開在畫面左上附近 |
| 開機自動啟動 | 啟用（最小化到系統列）|

若目標電腦已經有設定檔，安裝程式**只改上表這些鍵**，其餘設定原樣保留，
而且**不會動已經填好的 OCR 金鑰**。

**OCR 金鑰不會預先填入。** 畫面翻譯要用的話，到 <https://ocr.space/ocrapi>
用 email 申請免費金鑰（每月 25,000 次），填進 QTranslate 的
「選項 → 進階 → OCR API key」。

> **SmartScreen 警告**：這個安裝檔沒有數位簽章，第一次執行時 Windows 會顯示
> 「Windows 已保護您的電腦」。點「**其他資訊**」→「**仍要執行**」即可。

### 已經裝好 QTranslate，只想更新修正

對 `Fix-QTranslate.cmd` 按右鍵 →「以系統管理員身分執行」。它只替換
`Service.js`，不動其他任何東西，也不會改設定。

`Restore-Original.cmd` 可以隨時還原成原始檔（但原始版本已經無法翻譯）。

兩者都可重複執行，`Service.js.original` 這個原始備份永遠不會被覆蓋。

### 重新打包安裝檔

改過 `patch\Google Translate\Service.js` 之後，執行：

```powershell
.\build-installer.ps1
```

它會重新封裝內容、重新編譯，把新的 `QTranslate-Setup.exe` 放到 `dist\`。
需要 .NET SDK 9。

## 資料夾內容

| 路徑 | 說明 |
| --- | --- |
| `dist\QTranslate-Setup.exe` | 完整安裝檔（自帶 .NET，免安裝執行環境） |
| `Fix-QTranslate.cmd` | 只更新 `Service.js`，不動設定 |

## 已知未修項目

**Microsoft（Bing）服務**同樣無法使用，但成因不同：它依賴 `Options.IG`、
`Options.BingToken`、`Options.BingKey` 這幾個值，而這些是 `QTranslate.exe`
自己去 bing.com 抓網頁解析出來的，不是 `Service.js` 能控制的範圍。
要修的話得改寫成用 JS 的多階段請求鏈（`ResponseData` 的
`nextRequestHandler`）自行抓取權杖 —— 做得到，但屬於另一項工程。
